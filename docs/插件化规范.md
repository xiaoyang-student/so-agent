# 插件化规范

插件化把「内核控制面」与「可选能力」分离：沙箱、LLM、MCP、规则、观测
五类能力都可以由内置实现或外部插件提供。内核只依赖
`so_agent.plugins.contracts`，不反向导入具体插件实现。

当前状态（如实说明）：

| 类别 | 内置实现 | 外部插件 | 消费方接线 |
| --- | --- | --- | --- |
| sandbox | local / docker / podman / auto / cloud | 已支持，加载后即可用 `sandbox_backend=<name>` 选择 | 已接线 |
| llm | `openai_compatible`（含多供应商故障转移） | 已登记、可加载 | 现有装配仍直接调用 `build_chat_model`，按需迁移 |
| mcp | `directory`（外部 MCP 目录管理） | 同上 | 通过 `PluginRegistry.create` 取用 |
| rules | `builtin`（可机检验收规则） | 同上 | 通过 `PluginRegistry.create` 取用 |
| observability | `events`（事件日志） | 同上 | 通过 `PluginRegistry.create` 取用 |

---

## 1. 目录约定

```text
plugins/
  sandbox/
    example/
      plugin.yaml      # 清单
      plugin.py        # 入口模块
  llm/
  mcp/
  rules/
  observability/
```

- 第一级目录必须是五种类别之一；
- 第二级目录名必须等于清单 `id` 中类别前缀之后的短名；
- 每个插件目录必须包含 `plugin.yaml`（或 `plugin.yml`）；
- 入口文件必须是插件目录内的相对路径，允许子目录，但不得越界。

相对 `plugins_dir` 按进程当前工作目录解析。

---

## 2. 清单（plugin.yaml）

```yaml
id: sandbox.example          # <kind>.<name>；name 小写字母/数字/下划线/连字符
kind: sandbox                # sandbox | llm | mcp | rules | observability
version: 1.0.0               # x.y.z，可带 -pre / +build
entrypoint: plugin.py:create # <相对路径>.py:<可调用属性>
api_version: "1"             # 当前内核只接受主版本 1
description: 示例沙箱插件
capabilities: [execute]      # 小写标识，声明能力，不做安全授权
permissions: [process_exec]  # 声明申请权限，必须在已知权限集合内
secrets: [EXAMPLE_API_KEY]   # 只允许环境变量名，禁止明文密钥
sha256: "<64 位小写 hex>"    # 入口文件摘要；启用摘要钉住时必需
compatibility: ">=1.0,<2.0"  # 预留，当前仅记录
```

校验规则（任一不满足即拒绝启动）：

- 未知字段、错误类型、非法 id/版本/入口 → `PluginManifestError`；
- 目录名与 `kind`/`name` 不一致 → 拒绝；
- 未声明的权限 → 拒绝；`capabilities` 不是权限声明；
- `api_version` 主版本不符 → 拒绝；
- `entrypoint` 含 `..`、反斜杠、绝对路径，或解析后越出插件目录 → 拒绝；
- 启用 `plugins_require_hash` 但清单缺 `sha256`，或摘要不匹配 → 拒绝。

已知权限集合：`network_egress`、`filesystem_read`、`filesystem_write`、
`process_exec`、`secrets_read`。

## 3. 启用与启动行为

配置项（均可用 `SO_AGENT_` 前缀环境变量覆盖）：

```yaml
plugins_dir: plugins        # 插件根目录
plugins_enabled: ""         # 空：仅内置；"*"：加载全部；逗号分隔 id：仅启用列出项
plugins_require_hash: false # 强制入口文件摘要钉住
```

- 空 `plugins_enabled` 时只登记内置插件，不扫描、不导入外部目录；
- `"*"` 与具体 id 不能混用；
- 启用的 id 既非内置也未发现 → `PluginNotFoundError`；
- 外部插件与内置插件同 id → 重复注册错误，不覆盖内置实现；
- 清单/加载失败一律 fail-closed：CLI 打印 `[插件错误]` 并以退出码 2
  结束；Web 启动抛出 `RuntimeError`，不会带着缺失能力继续运行。

沙箱插件加载后自动注册到 `runtime.sandbox` 后端表，随后即可：

```yaml
sandbox_backend: example
```

或在构造时显式指定：

```python
from so_agent.runtime.sandbox import create_sandbox

sandbox = create_sandbox(context, backend="example")
```

## 4. 工厂契约

工厂是入口模块中的可调用对象，由消费方按类别传参：

```python
# sandbox：返回 SandboxBackend（见 runtime.sandbox）
def create(*, context, sandbox_dir, settings, python_executable):
    ...

# llm：返回 agents 模型对象
def create(*, config, config_path=None, client_factory=None, http_timeout=None):
    ...

# mcp / rules / observability：由消费方按内置实现签名传参
def create(**kwargs):
    ...
```

内置插件只是现有实现的薄适配，不复制逻辑：

- sandbox → `runtime.sandbox.create_sandbox`
- llm → `runtime.model_gateway.build_chat_model`
- mcp → `mcp.directory.MCPDirectoryManager`
- rules → `runtime.verification.evaluate_verification_rules`
- observability → `runtime.events.EventLogger`

外部插件与内置插件使用同一注册表：

```python
from so_agent.plugins import PluginRegistry, load_plugins

registry = load_plugins(settings)          # 启动期一次
provider = registry.create("sandbox", "example", context=context)
```

## 5. 安全模型

已实现的边界：

- **显式启用**：未列出的插件不会被发现、导入或执行；
- **清单收紧**：未知字段、未知权限、明文密钥、API 版本不符直接拒绝；
- **路径围栏**：入口必须是插件目录内的 `.py` 文件，阻止 `..` 与符号
  链接越界；
- **摘要钉住**：可选 `sha256`，生产环境建议开启 `plugins_require_hash`；
- **密钥不入清单**：`secrets` 只声明环境变量名，值由运行环境注入；
- **失败即拒绝**：加载失败不降级、不静默回退。

明确的限制：

- 当前为**进程内加载**，插件与内核同权限；`permissions` 是声明式约束，
  尚未由操作系统强制。只应加载受信任来源的插件；
- 来源不可信的插件未来需要在独立进程或沙箱中运行，该能力不在当前
  版本承诺范围内；
- `capabilities` 仅用于能力发现与展示，不构成授权。

---

## 6. 新增插件步骤

1. 在 `plugins/<kind>/<name>/` 下创建 `plugin.yaml` 与 `plugin.py`；
2. 清单 id 与目录名保持一致，声明最小权限与所需环境变量；
3. 计算入口文件摘要（可选但推荐）：

   ```bash
   python -c "from so_agent.plugins import sha256_file; print(sha256_file('plugins/sandbox/example/plugin.py'))"
   ```

4. 在配置中启用：`plugins_enabled: sandbox.example`；
5. 启动后校验：内置插件与外部插件都会出现在
   `PluginRegistry.names(kind)` 中；沙箱插件还应出现在
   `available_sandbox_backends()` 中；
6. 为插件补充一致性测试（同一套用例跑内置与外部实现）。
